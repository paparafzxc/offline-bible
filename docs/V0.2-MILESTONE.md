# Stillword v0.2 — Complete Offline Bible Library

## Goal

Ship a portable, genuinely offline Bible library with complete verse coverage for every bundled translation. The app must continue to open directly from `index.html` using the browser's `file://` scheme. Reading, chapter navigation, search, bookmarks, highlights, notes, and reading plans must not require a server, network request, CDN, or build step at runtime.

## v0.2 scope

### Bundled translations
- [ ] World English Bible (WEB), 66-book Protestant canon
- [ ] King James Version (KJV), 66-book Protestant canon
- [ ] American Standard Version (ASV, 1901), 66-book Protestant canon
- [ ] Ang Biblia (1905), subject to validation of the exact source edition and redistribution terms
- [ ] Ang Biblia (2001) is not bundled unless written redistribution permission is obtained from the Philippine Bible Society. Support a user-supplied local import as a separate feature only if it can be done without redistributing the text.

### Library requirements
- [ ] Every bundled translation contains all 66 books, all expected chapters, and all available verses.
- [ ] Book/chapter/verse identifiers are consistent across translations (OSIS book identifiers).
- [ ] Translation metadata records source URL, edition, language, license/rights statement, retrieval date, and integrity hash.
- [ ] A validation report checks book count, chapter counts, empty text, duplicate references, and verse coverage.
- [ ] Search works across the complete local corpus and supports translation filtering.
- [ ] Chapter navigation loads local data shards only.
- [ ] Translation switching preserves the current book/chapter when available.
- [ ] Existing bookmarks, highlights, notes, reading plans, and theme preferences survive the data migration.
- [ ] UI shows clear translation attribution and data provenance.
- [ ] No runtime network requests; test with networking disabled.

## Architecture decision: file:// compatibility

Do not use runtime `fetch()` to load local JSON. Modern browsers commonly block fetch requests from `file://` pages. The build pipeline will convert canonical source JSON into local JavaScript shards. The app can load a shard with a local `<script src="...">` element, which works with the existing folder-portable delivery model.

Proposed generated layout:

```
data/
  bible-data.js                 # existing book catalogue + bootstrap metadata
  library/
    WEB/
      Gen.js
      Exod.js
      ...
    KJV/
      Gen.js
      ...
    ASV/
      Gen.js
      ...
    AB1905/
      Gen.js
      ...
  search/
    WEB.js
    KJV.js
    ASV.js
    AB1905.js
sources/
  manifest.json                 # provenance, edition, license, SHA-256
scripts/
  build_library.py
  validate_library.py
```

Each shard registers one book under `window.BIBLE_LIBRARY[translationCode][osis]`. Shards are generated artifacts; source data and manifest remain auditable.

## Acceptance criteria

1. Automated validation reports 66/66 books and all expected chapters for each bundled translation.
2. Verse counts are non-zero for every chapter; duplicate or blank verse references fail validation.
3. Spot checks include Genesis 1, Psalm 23, John 1, John 3:16, and Revelation 22 in every bundled translation.
4. Full-text search finds known phrases from both testaments while offline.
5. The app opens from a copied folder on Windows without localhost, installation, or internet.
6. Browser DevTools shows no external requests and no failed local asset requests.
7. Export/import of personal data remains compatible or has a documented migration.

## Work breakdown

- **0.2.1 — Corpus and provenance:** acquire vetted complete source texts and record licensing.
- **0.2.2 — Build and validation pipeline:** normalize sources, generate local shards and search indexes, produce coverage report.
- **0.2.3 — Reader integration:** lazy-load local shards and support all bundled translations.
- **0.2.4 — Search and QA:** full-corpus search, offline test, regression test personal data.
- **0.2.5 — Release:** update version, README, changelog, and portable ZIP.

## Explicit non-goals

- No online API dependency.
- No automatic download of Bible text at runtime.
- No inclusion of copyrighted translation text without permission.
- No claim of completeness until the generated corpus passes validation.
